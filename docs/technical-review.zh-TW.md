## 虎牙播放

原本直接嵌入 `www.huya.com` 的完整直播間。實測時頁首及賽事資訊占據大部分窗格，播放器被擠到下方，且曾觀察到播放時間幾乎停止推進。現在將直播間路由到[虎牙站外播放器](https://liveshare.huya.com/iframe/660000)：

| 輸入 | 實際載入 |
| --- | --- |
| `https://www.huya.com/660000` | `https://liveshare.huya.com/iframe/660000` |
| `https://m.huya.com/lpl` | `https://liveshare.huya.com/iframe/lpl` |

房號與別名格式已對照虎牙的[播放器前端程式](https://hd.huya.com/h5/livesharePc/js/app.cdbc3c22.js)。首頁、分類、影片、活動及既有站外播放器網址保留原樣。

改善後以 Chrome for Testing 148.0.7778.96 載入實際擴充套件，四窗格中同時測試上述兩個來源。兩個來源均取得 1280 × 720 影片，播放時間與解碼影格持續增加；調整分隔線及切換語言保留原 iframe。觀察期間一個來源曾進入緩衝，設定狀態也正確顯示為緩衝中，而另一個來源繼續播放。

尚未取得使用者原先失敗的房間網址，因此上述結果僅代表測試來源與環境。虎牙服務、登入、地區、是否開台與自動播放政策仍會影響實際播放；沒有加入無限自動重試或第三方解析服務。

## 實作要點

- 網路規則更新排入同一個佇列，避免較慢的更新覆蓋較新的分頁狀態。只接受本套件 dashboard 主框架的安裝請求；空分頁清單會刪除規則，不會建立全域規則。規則錯誤會傳回介面。這些規則使用 Chrome 的 [session rules](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest) 與[分頁事件](https://developer.chrome.com/docs/extensions/reference/api/tabs)。
- 載入工作綁定窗格元素，換網址、關閉窗格或重試時使舊工作失效；未更動的 iframe 持續重用。重試一個來源不會套用其他來源尚未套用的網址。
- 狀態與重試按鈕集中在設定對話框。iframe 的載入完成不等於影片正在播放；只有來源內的可見 HTML video 狀態可確認播放，其他頁面顯示「頁面已載入・尚未確認播放」。巢狀 iframe 或自訂播放器可能只能取得頁面狀態。
- 大範圍 DOM 探索限制為 30 秒，期間合併密集變動。找到播放器後縮小觀察範圍；仍保留低頻檢查，以支援稍後才出現或被替換的播放器。尚未量測 CPU／記憶體節省比例。
- 延續原生 JavaScript 與 MV3 架構，執行時不需新增前端框架或播放器程式庫。

## 驗證

44 項離線測試涵蓋來源路由、網址容錯、API 逾時與重試、規則生命週期／權限檢查／非同步順序，以及播放器觀察的範圍、節流、截止與恢復行為。

瀏覽器整合測試以本地回應內容與 canvas 影片，驗證以下情境，無需外部直播服務：

1. 慢速來源不阻塞另一窗格。
2. 過期回應不覆蓋新網址，待解析來源在交換位置後載入正確窗格。
3. 單格重試保留其他 iframe 及未套用的輸入。
4. 真實 HTML video 播放／暫停事件經由 content script 回報至版面。
5. 實際 8 秒逾時只讓該來源顯示錯誤。
6. 不完整網址、對話框焦點循環、Escape 與鍵盤分隔線。
7. 規則安裝失敗可見，重試後消除提示。
8. 真實擴充套件中兩個版面共存，導向外頁、關閉分頁後清理規則。
9. YouTube 嵌入失敗切換至完整頁面，播放器被替換後重新套用版面，以及 YesLive 播放器擷取。

## 後續可選方向

- 若常用 `.m3u8`／`.mpd`，再增加本地 HLS／DASH 播放頁；目前仍交給 iframe／瀏覽器處理，需另驗證 CORS、codec、DRM 與套件大小。
- 隨平台數量增加，可將純來源解析邏輯抽出獨立模組；目前優先穩定既有輕量架構。
- 建立四路長時間播放的 CPU、記憶體與斷線恢復基準，量測後再決定是否需要更多節流或背景暫停策略。

## 套用更新

到 `chrome://extensions` 重新載入套件，再重新整理已開啟的 Stream Layout 分頁。原本的來源網址與版面設定可以沿用。若某個來源失敗，打開設定對話框，使用該來源的「重試」。
